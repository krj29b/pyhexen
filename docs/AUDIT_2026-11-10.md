# PyHexen implementation audit (2026-11-10)

**Bottom line:** most of the engine has been built and tested as library code, but **the playable game is only partly wired together**. `PROGRESS.md` lists every task as `DONE`, and several of those claims overstate what was actually verified. That includes claims made by this agent in earlier sessions.

## 2. Rule violations (AGENTS.md hard rules)

> [!WARNING]
> **Floats in the simulation.** In [lights.py](../src/pyhexen/sim/specials/lights.py#L33-L34), `LightFade` uses `float` for `step` and `current`. The reference (`p_lights.c:39-41`, `:181`) uses fixed-point `value2 = FixedDiv(...)` and has different end conditions (`tics2` direction). This breaks the determinism rule, and fade timing differs from vanilla.

- **Layering:** [savegame.py](../src/pyhexen/sim/savegame.py#L26) imports `ui.menu`. It is under `TYPE_CHECKING`, so it has no runtime effect, but it still breaks the rule that `sim` must not depend on `ui`. Save management arguably belongs in `app/`.

## 3. Integration gaps: built and tested, but not reachable in the game

`__main__.py` only wires up the renderer, the status bar, weapon sprites and the menu. These modules are **never imported outside tests**:

| Module | Consequence in the actual game |
|---|---|
| `audio/channels.py`, `audio/music.py`, `audio/sndseq_player.py` | **No sound or music at all** |
| `ui/automap.py` | No automap (Tab does nothing) |
| `ui/messages.py` | No pickup messages or ACS print text |
| `ui/intermission.py` | No title screen, hub text or finale; the game boots straight into `--warp` |
| `sim/hub.py`, `sim/savegame.py` (only `compute_wad_checksum` is used) | No hub persistence, and save/load from the menu does nothing |

> [!IMPORTANT]
> **Level exits do nothing.** `exit_normal`, `exit_secret` and `Teleport_NewMap` emit a `MapExit` event ([transitions.py](../src/pyhexen/sim/transitions.py#L294-L308)), but **nothing subscribes to it**. You cannot leave MAP01 in normal play. The "multi-hub transition" checks in T14.5 drove `HubManager` directly, which skips this path entirely.

Also missing: a "New Game" flow from the menu (class or skill selection doesn't start a game) and death/respawn handling in the loop.
